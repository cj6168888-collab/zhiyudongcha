> 从愿景到现实：一份科学、详细的功能完善方案

---

## 📊 开发背景

### 当前实现状态

| 状态 | 数量 | 比例 | 说明 |
|------|------|------|------|
| ✅ 已实现 | 12项 | 27% | 可直接使用 |
| ⚠️ 部分实现 | 21项 | 47% | 有框架，需完善 |
| ❌ 未实现 | 12项 | 27% | 需从头开发 |

### 核心技术栈

- **前端**: React 18 + TypeScript + Tailwind CSS + shadcn/ui
- **后端**: Express.js + PostgreSQL + Drizzle ORM
- **AI服务**: DashScope (云端) + Ollama (私有GPU)
- **移动端**: Capacitor (Android/iOS)
- **实时通信**: WebSocket

## 🔧 Phase 1: 诚实基础 (第1-2周)

> **目标**: 完成核心AI基础设施，让三级处理架构真正运转

### 📋 任务清单

#### 1.1 本地LLM推理引擎 [P0] 
**预计工时**: 3天

```
目标：让Android App能够离线运行本地AI模型

技术方案：
├── 1. 完善 LocalLLMPlugin.java
│   ├── 集成 llama.cpp Android 绑定
│   ├── 实现模型加载/卸载生命周期
│   ├── 实现 chat() 方法的真实推理
│   └── 添加 Worker Thread 避免UI阻塞
│
├── 2. 模型管理
│   ├── 首次启动模型选择界面
│   ├── 后台下载进度显示
│   ├── 模型文件完整性校验
│   └── 支持模型切换
│
└── 3. 客户端逻辑
    ├── client/src/lib/local-llm.ts 完善
    ├── 离线/在线自动切换
    └── 降级策略（本地失败→云端）

**验收标准**:
- [ ] 飞行模式下能完成基础对话
- [ ] 模型下载进度准确显示
- [ ] 推理速度 > 5 tokens/秒

**依赖**: Android NDK, llama.cpp

#### 1.2 三级智能路由 [P0]
**预计工时**: 2天

```
目标：根据任务类型和敏感度自动选择处理层级

文件：server/services/hybrid-ai.ts

路由规则：
┌──────────────────┬────────────────┬───────────────┐
│ 任务类型          │ 敏感度         │ 路由目标       │
├──────────────────┼────────────────┼───────────────┤
│ 闲聊/简单问答     │ 低             │ 本地 3B       │
│ 日程/提醒        │ 中             │ 私有 Ollama   │
│ 法律/财务分析    │ 高(隐私)       │ 私有 Ollama   │
│ 图像理解/语音    │ 低             │ DashScope云   │
│ 复杂推理/搜索    │ 低             │ DashScope云   │
└──────────────────┴────────────────┴───────────────┘

实现要点：
1. 添加 TaskClassifier 服务
2. 敏感词/意图检测（本地规则优先）
3. 路由决策日志（可审计）
4. 用户可配置偏好（隐私优先/速度优先）
```

**验收标准**:
- [ ] 敏感话题自动走私有服务器
- [ ] 路由决策在 <50ms 内完成
- [ ] 路由日志可在设置中查看

#### 1.3 零幻觉知识库完善 [P0]
**预计工时**: 2天

```
目标：让专业回答有据可查，低置信度主动拒绝

文件：server/services/zero-hallucination.ts

当前问题：

完善方案：

   └── 输出包含 [来源1][来源2] 标注

**验收标准**:
- [ ] 法律问题返回条款引用

- [ ] 低于90%置信度返回拒绝模板

#### 1.4 生物认证持久化 [P0]
**预计工时**: 2天

```
目标：声纹/面容数据持久化，真正可用的身份验证

当前问题：
- biometric-auth 仅内存存储
- 无实际验证逻辑

文件：server/services/biometric-auth.ts

完善方案：
1. 数据库表
   CREATE TABLE biometric_profiles (
     id SERIAL PRIMARY KEY,
     user_id VARCHAR(50) UNIQUE,
     face_embedding VECTOR(512),
     voice_embedding VECTOR(256),
     created_at TIMESTAMP,
     updated_at TIMESTAMP
   );

2. 注册流程
   ├── 面容：采集3张不同角度照片
   ├── 声纹：采集3段不同语句
   └── DashScope 生成嵌入向量

3. 验证流程
   ├── 实时采集 vs 存储向量
   ├── 余弦相似度阈值 0.85
   └── 验证失败计数锁定
```

**验收标准**:
- [ ] 生物特征持久化到数据库
- [ ] 换设备后仍可验证
- [ ] 照片攻击无法通过验证

#### 1.5 后台任务基础设施 [P0]
**预计工时**: 1天

```
目标：为后续功能提供定时任务和队列支持

技术选型：
- 简单方案：node-cron（已有依赖）
- 完整方案：BullMQ + Redis（需要时升级）

实现内容：
1. server/services/scheduler.ts
   ├── 每日凌晨3点：梦境整理
   ├── 每小时：主动关怀检查
   ├── 每5分钟：提醒触发
   └── 任务执行日志

2. 任务状态表
   CREATE TABLE scheduled_jobs (
     id SERIAL PRIMARY KEY,
     job_type VARCHAR(50),
     status VARCHAR(20),
     last_run TIMESTAMP,
     next_run TIMESTAMP,
     result JSONB
   );
```

**验收标准**:
- [ ] 定时任务按时执行
- [ ] 任务执行历史可查询
- [ ] 任务失败自动重试

## ⚠️ 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 本地推理性能不足 | 用户体验差 | 降级到更小模型/云端 |
| 外部AI服务成本 | 预算超支 | 本地优先，按需调用 |
| 单人开发瓶颈 | 进度延迟 | 优先核心功能，其他迭代 |
| 法律合规风险 | 合同功能受限 | 添加免责声明 |
| 隐私数据泄露 | 信任危机 | 本地优先+端到端加密 |
