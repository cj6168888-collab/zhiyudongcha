# 感知、外设与 Conversation 产品交付计划

> 版本：2026-04-30 v1
> 状态：产品交付基线
> 对应文档：
> - `docs/12_PERCEPTION_DEVICE_AND_CONVERSATION_STRATEGY.md`
> - `docs/technical/20_PERCEPTION_DEVICE_IMPLEMENTATION_SPEC.md`

## 产品目标

把 Omi 的外脑闭环、小智/ESP32 的语音外设便利性，融合进生语助手的领航者体系。

最终体验：

```text
用户先在手机端唤醒自己的领航者。
没有外设，也能聊天、记事、创建任务、确认动作。
有 ESP32 外设时，同一个领航者多了一个身边的语音身体。
有 Omi 时，Omi 的历史会话可以进入我们的主权空间。
所有输入先成为 Conversation，再沉淀为记忆、任务、事件、项目更新。
```

## 产品原则

1. 手机端是意识诞生地。
2. 外设是可选增强，不是使用门槛。
3. Omi 是可拔插感知源，不是系统底座。
4. Conversation 先于 Memory、Task、Event。
5. 所有长期记忆必须可追溯。
6. 高风险动作必须确认。
7. 闲聊模式不强制结构化。
8. 外设不独立拥有人格和主记忆。

## Release P0：Conversation 底座

### 用户故事

作为主人，我希望自己说过、传过、录过的重要内容先成为一段可回看的 Conversation，而不是直接散落成很多无法追溯的记忆和任务。

作为主人，我希望系统能从一段 Conversation 中提出记忆、任务、事件候选，并让我确认。

作为主人，我希望未来看到某条任务或记忆时，能回到它来自哪段对话或材料。

### 功能包

- Conversation 列表。
- Conversation 详情。
- Transcript/Segment 展示。
- Summary 展示。
- 记忆候选。
- 任务候选。
- 事件候选。
- 接受、编辑、拒绝候选。
- 回跳来源。

### 页面

- `ConversationInbox`
- `ConversationDetail`
- `CandidateReview`

### 验收标准

- 用户在聊天中输入一段含任务的话，系统生成 Conversation。
- Conversation 后处理生成 TaskCandidate。
- 用户接受 TaskCandidate 后创建任务。
- 任务详情能回跳原 Conversation。
- 用户拒绝 MemoryCandidate 后不写入长期记忆。
- 删除 Conversation 时，系统提示会影响来源追溯。

### 不做

- 不做全天候录音。
- 不做 Omi 实时同步。
- 不做 ESP32 外设。
- 不做屏幕常驻感知。

## Release P1：手机端觉醒与设备绑定

### 用户故事

作为主人，我希望先在手机端完成名字、关系、性格、声音和边界设置，再绑定任何外设。

作为主人，我希望看到哪些设备承载了同一个领航者，并能随时撤销。

### 功能包

- 身份觉醒完成状态。
- 名字、关系、性格、声音、边界配置入口。
- 设备绑定码。
- 设备列表。
- 设备状态。
- 允许模式设置。
- 撤销设备。

### 页面

- `Awakening`
- `DeviceBinding`
- `DeviceStatus`
- `DevicePermissions`

### 验收标准

- 未完成觉醒时，用户不能绑定外设人格。
- 完成觉醒后，可以生成绑定码。
- 设备绑定后显示在线状态和允许模式。
- 撤销设备后，该设备无法继续发起请求。
- 高风险动作仍要求手机端确认。

### 不做

- 不让外设独立设置人格。
- 不在外设保存长期记忆。
- 不让外设直接执行发送、删除、付款、外传。

## Release P2：ESP32 小智外设融合

### 用户故事

作为主人，我希望桌面上有一个低成本语音外设，可以叫醒她、闲聊、快速记事、创建提醒。

作为主人，我希望外设只是同一个领航者的身体，而不是另一个机器人。

作为主人，我希望外设断网或失败时明确告诉我，而不是假装事情已经完成。

### 功能包

- XiaoZhiBridge WebSocket。
- 外设 hello/binding_required/hello_ack。
- 语音或文本事件接入。
- 闲聊模式。
- 快速记事模式。
- 明确记录模式。
- 任务请求模式。
- 外设状态灯/屏幕状态命令。
- 离线缓存和重连策略。

### 关键流程

```text
外设首次启动
  -> 显示绑定码
  -> 手机端绑定
  -> 外设获得名字、声音、唤醒词、允许模式
  -> 用户唤醒并说“帮我记一下”
  -> 后端生成 Conversation
  -> 外设播报“我记下了，稍后会整理给你确认”
```

### 验收标准

- 未绑定外设不能创建 Conversation。
- 绑定外设能进入闲聊模式。
- “帮我记一下”生成 Conversation。
- “明天提醒我...”生成 TaskCandidate。
- 高风险请求时外设显示“请在手机确认”。
- 断网后外设进入离线状态，不声称任务完成。

### 不做

- 不做全天候无感监听。
- 不做长会议完整转写。
- 不做外设本地长期记忆。
- 不做外设本地大模型人格推理。

## Release P3：Omi Importer

### 用户故事

作为已经使用 Omi 的用户，我希望把 Omi 里的会话、记忆和任务导入生语助手，让它们进入我的主权空间。

作为主人，我希望 Omi 断开或关闭后，已导入的数据仍然属于我。

### 功能包

- Omi 连接配置。
- Omi 批量导入。
- Omi Conversation 映射。
- Omi Memory 映射为 MemoryCandidate。
- Omi Action Item 映射为 TaskCandidate。
- 导入日志。
- 同步状态。
- 断开连接。

### 验收标准

- Omi Conversation 导入后成为本地 Conversation。
- Omi Memory 不直接进入长期记忆，必须成为候选。
- Omi Action Item 不直接创建任务，必须成为候选。
- 重复导入不会重复创建。
- Omi 不可用不影响本地系统。
- 每条导入内容都保存 remote id、source、importedAt、hash 或 raw payload。

### 不做

- 不依赖 Omi 作为主数据源。
- 不暴露 Omi 内部结构为我们的核心结构。
- 不让 Omi App 绕过主权守护。

## Release P4：桌面与屏幕感知

### 用户故事

作为主人，我希望桌面端能在我允许时理解当前屏幕，把重要片段变成可追溯的 Conversation Segment。

### 功能包

- 屏幕感知开关。
- 当前屏幕截图。
- OCR。
- 屏幕摘要。
- 敏感内容检测。
- 屏幕 Segment 回跳。

### 验收标准

- 屏幕感知默认关闭。
- 开启时有持续可见状态。
- 敏感页面触发确认或本地优先策略。
- 屏幕摘要能回跳截图证据。

## Release P5：梦境复盘融合

### 用户故事

作为主人，我希望每天的 Conversation 自动进入梦境复盘，第二天给我遗漏任务、项目风险、关系变化和记忆整理建议。

### 功能包

- Conversation Reflection Queue。
- 每日复盘。
- 任务遗漏发现。
- 项目风险发现。
- 人物关系变化发现。
- 记忆去重和冲突提示。
- 第二天建议。

### 验收标准

- 每晚从 Conversation 生成复盘输入。
- 复盘输出可生成候选任务、候选记忆、风险提示。
- 用户可以接受或拒绝复盘建议。

## 关键指标

### P0 指标

- Conversation 创建成功率 >= 99%。
- Candidate 生成成功率 >= 95%。
- 应用后回跳成功率 = 100%。
- 高风险候选确认覆盖率 = 100%。

### P2 指标

- 外设绑定成功率 >= 95%。
- 外设心跳在线状态准确率 >= 99%。
- 未绑定设备请求拦截率 = 100%。
- 高风险请求直接执行率 = 0%。

### P3 指标

- Omi 导入幂等成功率 = 100%。
- Omi 断开后主系统可用率 = 100%。
- 导入内容来源追溯率 = 100%。

## 排期建议

1. P0 先做两周：Conversation 底座和 Inbox。
2. P1 一周：觉醒状态和设备绑定。
3. P2 两周：ESP32 外设最小闭环。
4. P3 一周：Omi 批量导入。
5. P4/P5 根据 P0-P3 真实使用反馈推进。

## 风险

### 最大产品风险

用户感觉系统变复杂，而不是更有生命感。

缓解：

- 手机端继续以觉醒和关系为第一体验。
- Inbox 只展示需要用户处理的少量候选。
- 闲聊不强制落地。

### 最大技术风险

Conversation 层和现有 assistant/task/vault 重叠。

缓解：

- 渐进迁移。
- 先让 assistant 写入或关联 Conversation。
- 不立即重写现有任务和记忆系统。

### 最大生态风险

Omi API 或小智固件变化。

缓解：

- Provider Adapter 隔离。
- 本地固化。
- 导入优先于实时依赖。
- ESP32 Runtime 自己定义协议。
