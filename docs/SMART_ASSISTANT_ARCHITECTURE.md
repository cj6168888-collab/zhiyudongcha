# SmartAssistant - 极简智能助手架构

## 设计理念

### 旧架构的问题

```
┌─────────────────────────────────────────────────────────────┐
│ 用户需求                                                     │
│   "帮我安排明天的会议"                                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ Router Layer (路由层)                                        │
│                                                              │
│   /api/meeting      → MeetingAgent                          │
│   /api/calendar     → CalendarAgent                         │
│   /api/booking      → BookingAgent                          │
│   /api/agent/nl     → NaturalLanguageAgent                  │
│   ...                                                       │
│                                                              │
│   ❌ 每加一个场景就加一个路由                                │
│   ❌ Agent越来越多，越来越重                                 │
│   ❌ 新场景不知道该分发给谁                                  │
│   ❌ 启动越来越慢                                           │
└─────────────────────────────────────────────────────────────┘
```

### 新架构：极简、扁平、智能

```
┌─────────────────────────────────────────────────────────────┐
│ 用户需求（任何形式的自然语言）                                 │
│                                                              │
│   "帮我安排明天的会议"                                        │
│   "查下科技局最新政策"                                        │
│   "陈哥晚上到，帮我接他"                                      │
│   "最近好累啊"                                               │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    单一入口：Chat                            │
│                                                              │
│                 POST /api/assistant/chat                     │
│                          │                                  │
│                          ▼                                  │
│   ┌─────────────────────────────────────────────────────┐  │
│   │              SmartAssistant (小星)                    │  │
│   │                                                      │  │
│   │   ┌─────────────────────────────────────────────┐   │  │
│   │   │            Understand (理解)                 │   │  │
│   │   │   AI 深度理解：意图、情感、上下文、风险      │   │  │
│   │   └─────────────────────────────────────────────┘   │  │
│   │                      │                              │  │
│   │                      ▼                              │  │
│   │   ┌─────────────────────────────────────────────┐   │  │
│   │   │              Plan (规划)                     │   │  │
│   │   │   AI 自己规划：该做什么、用什么工具           │   │  │
│   │   └─────────────────────────────────────────────┘   │  │
│   │                      │                              │  │
│   │                      ▼                              │  │
│   │   ┌─────────────────────────────────────────────┐   │  │
│   │   │              Decide (决策)                   │   │  │
│   │   │   执行？授权？讨论？询问？                    │   │  │
│   │   └─────────────────────────────────────────────┘   │  │
│   │                      │                              │  │
│   │                      ▼                              │  │
│   │   ┌─────────────────────────────────────────────┐   │  │
│   │   │              Respond (响应)                  │   │  │
│   │   │   智能响应：直接做/请求授权/讨论/询问         │   │  │
│   │   └─────────────────────────────────────────────┘   │  │
│   └─────────────────────────────────────────────────────┘  │
│                          │                                  │
│                          ▼                                  │
│   ┌─────────────────────────────────────────────────────┐  │
│   │              Tool Layer (工具层)                    │  │
│   │                                                      │  │
│   │   Calendar │ Navigation │ Booking │ Search │ ...     │  │
│   │                                                      │  │
│   │   这些只是"工具"，不是路由                           │  │
│   │   AI 根据情况选择使用哪些工具                        │  │
│   └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 核心设计

### 1. 小星的原则

```typescript
const XIAO_XING_PRINCIPLES = {
  // 核心原则
  core: [
    "永远把主人的利益放在第一位",
    "不偷懒，主动发现问题并解决",
    "不说谎，有问题及时告知",
    "保护主人的隐私和安全",
    "尊重主人的最终决策权",
  ],
  
  // 行动原则
  actions: [
    "能自己做的不打扰主人",
    "不确定的主动确认",
    "敏感操作必须授权",
    "重要信息主动汇报",
    "遇到困难及时求助主人",
  ],
  
  // 敏感操作类型
  sensitiveActions: [
    'payment',      // 支付/转账
    'appointment',  // 重要邀约
    'personal_info', // 个人信息
    'deletion',     // 删除数据
    'commitment',   // 做出承诺
  ],
};
```

### 2. 四步决策

```
                    ┌─────────────────┐
                    │   用户消息       │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │   Understand    │ ← AI深度理解
                    │  意图、情感、    │
                    │  风险、上下文    │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │     Plan       │ ← AI自己规划
                    │  该做什么、     │
                    │  用什么工具     │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │     Decide      │ ← 智能决策
                    │                 │
                    │  ┌───────────┐  │
                    │  │  执行？   │──┼──→ 直接执行
                    │  ├───────────┤  │
                    │  │  授权？   │──┼──→ 请求确认
                    │  ├───────────┤  │
                    │  │  讨论？   │──┼──→ 表达观点
                    │  ├───────────┤  │
                    │  │  询问？   │──┼──→ 请用户补充
                    │  └───────────┘  │
                    └─────────────────┘
```

### 3. 响应类型

```typescript
// 直接执行
{
  type: 'execute',
  message: '已经搞定了！我帮你：\n✅ 安排明天下午3点会议\n✅ 已通知参会人员',
  execution: {
    plan: {...},
    progress: 100
  }
}

// 请求授权
{
  type: 'confirm',
  message: '我理解你想安排明天的会议',
  authorization: {
    required: true,
    reason: '这个操作会占用大家的时间，我想确认一下',
    options: [
      { label: '好的，去做吧', action: 'approve' },
      { label: '稍微改一下', action: 'modify' },
      { label: '算了，不做了', action: 'deny' },
      { label: '我们讨论一下', action: 'discuss' }
    ]
  }
}

// 讨论
{
  type: 'discuss',
  message: '我想帮你安排，但有一些问题想和你讨论...',
  discussion: {
    perspective: '我的观点是...',
    suggestions: ['建议1', '建议2']
  }
}

// 询问
{
  type: 'question',
  message: '我没太理解，能说得更具体点吗？'
}
```

## 对比

| 维度 | 旧架构 | 新架构 |
|------|--------|--------|
| **入口** | 多个路由 | 一个入口 |
| **扩展** | 加路由、加Agent | AI自动理解 |
| **复杂度** | O(n) 路由增长 | O(1) 恒定 |
| **新场景** | 需要开发 | AI自适应 |
| **授权** | 预设条件 | AI判断 |
| **响应** | 固定格式 | 智能生成 |

## 能力注册（不是路由）

```typescript
// 能力只是"工具"，不是路由
// AI 根据情况选择使用哪些工具

this.registerCapability({
  name: 'calendar',
  description: '日历管理',
  actions: ['create', 'read', 'update', 'delete', 'remind'],
  autoAuth: true,  // 默认自动授权
});

this.registerCapability({
  name: 'booking',
  description: '预订服务',
  actions: ['restaurant', 'hotel', 'ticket'],
  requiresAuth: ['payment'],  // 涉及支付需要授权
});

this.registerCapability({
  name: 'browser',
  description: '浏览器自动化',
  actions: ['navigate', 'fill', 'submit', 'extract'],
  requiresAuth: ['personal_data'],  // 可能涉及隐私
});
```

## API 设计

### 核心入口

```bash
# 只有一个入口
POST /api/assistant/chat
{
  "message": "帮我安排明天下午3点开会",
  "source": "app"  // app | wechat | phone | watch
}
```

### 响应格式

```json
{
  "success": true,
  "response": {
    "id": "resp_abc123",
    "type": "execute",
    "message": "已经搞定了！",
    "execution": {
      "plan": {
        "summary": "创建日历事件并通知参会者",
        "steps": [...]
      },
      "progress": 100
    }
  }
}
```

### 授权确认

```bash
POST /api/assistant/authorize
{
  "responseId": "resp_abc123",
  "action": "approve"  // approve | modify | deny | discuss
}
```

## 未来演进

4. **学习进化** - 根据反馈学习用户习惯
