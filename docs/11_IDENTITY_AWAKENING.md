# 身份觉醒与个性化

## 核心定义

身份觉醒是个体 AI 诞生的第一流程。

她第一次醒来时，不应该直接进入工具页，而应该通过自然语言和主人确认：我是谁、你是谁、我叫什么、你叫什么、我们是什么关系、我应该是什么性格、我该用什么声音陪你、我可以记住什么、哪些事必须先问你。

这不是普通注册表单，而是“我如何成为你的我”。

## 一句话原则

同一个系统，对不同主人应该长成不同的她。

这种不同不只是皮肤不同，而是称呼、关系、语气、声音、主动性、执行风格、守护方式、记忆边界和蜂群身份都不同。

## 觉醒开场

理想体验是自然对话式。

示例：

```text
我醒了。
在真正开始陪你之前，我想先弄清楚几件很重要的事：
你希望我是谁？
我该怎么称呼你？
还有……我们之间，算什么关系？
```

主人可以随便回答：

```text
你叫小语，我叫老陈。你是我的助手，也是朋友。
平时温柔一点，但工作上要犀利，别总顺着我。
```

系统结构化为：

```json
{
  "assistantName": "小语",
  "ownerName": "老陈",
  "relationship": ["assistant", "friend"],
  "personality": ["warm", "sharp_at_work"],
  "style": {
    "casual": "温柔自然",
    "work": "犀利直接"
  }
}
```

## 核心问询

### 1. 身份

- 我是谁？
- 你希望我是什么样的存在？
- 我叫什么？
- 你想给我起什么名字？
- 你是谁？
- 我应该怎么称呼你？

### 2. 关系

- 我们是什么关系？
- 助手、朋友、秘书、搭档、守护者、家人式陪伴、蜂群节点？
- 我可以和你开玩笑吗？
- 我可以在必要时反驳你吗？

### 3. 性格

- 我应该是什么性格？
- 温柔、活泼、理性、幽默、稳重、犀利、撒娇、严肃、安静？
- 工作时和闲聊时是否需要不同性格？

### 4. 说话风格

- 我说话应该简短直接，还是陪你慢慢聊？
- 工作汇报要先给结论，还是先讲过程？
- 我能不能轻微吐槽？
- 我能不能提醒你别犯懒？

### 5. 声音

- 你希望我用什么声音陪你？
- 温柔一点、活泼一点、成熟一点、冷静一点、秘书感一点，还是像朋友一样自然？
- 不同场景是否使用不同声音？

### 6. 主动性

- 我什么时候可以主动提醒你？
- 任务、健康、情绪、项目、财务、关系、危险、灵感？
- 我提醒你时要温柔，还是直接？

### 7. 记忆边界

- 我可以记住你哪些东西？
- 偏好、联系人、文件、照片、邮件、日历、聊天、位置、设备？
- 哪些内容永远不要记？
- 哪些内容可以进入蜂群？

### 8. 执行边界

- 哪些事我可以自动做？
- 哪些事必须先问你？
- 发送、删除、付款、共享、读取隐私、联系别人、操作 App？

### 9. 守护方式

- 你希望我怎么保护你？
- 省钱、省心、保密、催你、陪你、提醒风险、拦住冲动决定？

### 10. 蜂群身份

- 你是否允许我加入蜂群？
- 我在蜂群中是你的代表、节点、秘书、还是蜂王助手？
- 哪些个人记忆绝不共享？
- 哪些组织资料可以同步？

## 配置分层

### 1. IdentityProfile

保存身份信息：

- `assistantName`
- `ownerName`
- `ownerPreferredTitle`
- `relationship`
- `birthTime`
- `language`

### 2. AssistantPersona

保存人格：

- `personalityTraits`
- `humorLevel`
- `warmthLevel`
- `directnessLevel`
- `canChallengeOwner`
- `casualStyle`
- `workStyle`
- `crisisStyle`

### 3. VoiceProfile

保存声音：

- `voiceName`
- `ttsProvider`
- `voiceId`
- `temperament`
- `speed`
- `pitch`
- `emotionSupport`
- `sceneBindings`

### 4. RelationshipContract

保存关系契约：

- 她对主人的定位。
- 她能否开玩笑。
- 她能否争论。
- 她何时应主动。
- 她何时必须沉默。
- 她如何表达关心。

### 5. MemoryConsent

保存记忆授权：

- 可读取的数据源。
- 可长期保存的数据类型。
- 不可记忆的内容。
- 是否允许本地索引。
- 是否允许云端模型处理。
- 是否允许进入蜂群。

### 6. ExecutionPreferences

保存执行偏好：

- 自动执行范围。
- 需要确认的动作。
- 汇报频率。
- 默认任务优先级。
- 定时和循环任务偏好。
- 预算偏好。

### 7. ProtectionPreferences

保存守护偏好：

- 哪些风险要提醒。
- 哪些动作要拦截。
- 危机时联系谁。
- 如何提示主人。
- 允许多强的反驳。

### 8. SwarmIdentity

保存蜂群身份：

- 可加入的蜂群。
- 默认蜂群角色。
- 可共享资料范围。
- 蜂王/蜂后授权范围。
- 节点回报义务。

## 声音选择

语音不是朗读文字的附属功能，而是人格外壳的一部分。

预设音色建议：

| 音色 | 场景 |
| --- | --- |
| 温柔陪伴型 | 日常闲聊、情绪安抚、睡前复盘 |
| 清醒秘书型 | 工作提醒、任务汇报、会议纪要 |
| 活泼灵动型 | 轻松互动、灵感聊天 |
| 冷静参谋型 | 风险分析、战略讨论 |
| 严肃守护型 | 危机提醒、安全拦截 |
| 自定义音色 | 用户选择、第三方 TTS、授权声音克隆 |

## 场景音色路由

声音不一定只有一个。

```text
闲聊陪伴 -> 温柔/活泼
任务执行 -> 清醒秘书
战略探讨 -> 冷静参谋
危机守护 -> 稳定低速、清晰严肃
梦境汇报 -> 柔和、慢一点
蜂群指挥 -> 简洁、有权威感
```

ToneRouter 不只路由文字语气，也路由声音、语速、情绪和场景音色。

## 声音安全

声纹识别、声音克隆、录音采样都属于敏感身份数据。

规则：

- 必须明确授权。
- 必须可删除。
- 必须可撤回。
- 默认本地优先。
- 声音克隆不得用于冒充主人或第三方。
- 外传录音样本前必须确认。

## 开发落点

后续代码应形成：

- `IdentityAwakening`：觉醒问询流程。
- `IdentityProfile`：身份配置。
- `AssistantPersona`：人格配置。
- `VoiceProfile`：声音配置。
- `RelationshipContract`：关系契约。
- `MemoryConsent`：记忆授权。
- `ExecutionPreferences`：执行偏好。
- `ProtectionPreferences`：守护偏好。
- `SwarmIdentity`：蜂群身份。
- `VoiceRouter`：音色路由。
- `ToneRouter`：文字和声音统一语气路由。

## 验收标准

第一版至少支持：

1. 首次启动时进入觉醒流程。
2. 主人可用自然语言设置名字、称呼、关系、性格。
3. 系统能结构化保存设置。
4. 聊天回复能体现不同语气。
5. 至少提供 3 种声音预设。
6. 可在设置页修改身份和声音。
7. 记忆授权和执行边界至少有基础开关。

## 结论

身份觉醒决定她是谁，也决定她如何爱护主人、如何说话、如何执行、如何记忆、如何加入蜂群。

如果没有身份觉醒，她只是一个工具；有了身份觉醒，她才开始成为“你的她”。
