## 核心升级

### 1. 声纹识别 - 分清谁是谁

```
原始对话：
"我晚上10点到郑州，你有时间来接我吗？"
"有的兄弟，需要我帮你安排房间吗？到了咱们去小酌一杯。"
"好的陈哥，10点见，我从高铁站东出站口出。"
"好的兄弟，我的车牌号0L5Z7"

                    ↓
        VoicePrintAgent 分析

识别结果：
┌─────────────────────────────────────┐
│ 说话人A (兄弟)                        │
│   "我晚上10点到郑州，你能来接我吗？"  │
│   "好的陈哥，10点见..."              │
│   "好的兄弟，我的车牌号0L5Z7"        │
│   → 承诺：10点接人 + 安排房间        │
│   → 提供：车牌号 0L5Z7               │
├─────────────────────────────────────┤
│ 说话人B (陈哥)                        │
│   "有的兄弟，需要我帮你安排房间吗？"  │
│   "到了咱们去小酌一杯"               │
│   → 承诺：安排房间 + 小酌            │
└─────────────────────────────────────┘
```

## API 接口

### 对话分析

```bash
# 从对话中分析
POST /api/proactive/process
{
  "content": "我晚上10点到郑州...",
  "source": "wechat",
  "participants": ["兄弟", "陈哥"]
}

# 从对话直接推荐
POST /api/recommend/from-conversation
{
  "conversation": "我晚上10点到郑州，能来接我吗？...",
  "source": "wechat"
}
```

## 关键设计

### 1. 声纹分离的必要性

```
问题：
"我晚上10点到郑州" —— 谁说的？

解决方案：
• 通过称呼关系判断："陈哥"是称呼对方
• 通过"我的车牌"判断：这是陈哥提供的车辆信息
• 通过回应判断："好的陈哥"是对陈哥的回应
```

### 2. 主动推荐的触发

```
时机：
• 检测到约定（接站、送人）
• 检测到住宿需求（"安排房间"）
• 检测到餐饮需求（"小酌"、"吃饭"）

方式：
• 直接推荐最优选项
• 询问是否需要帮助
• 一键预订
```

### 3. 上下文关联

```
陈哥来电
    │
    ├──→ 提取约定: 22:00 接站
    │
    ├──→ 提取信息: 车牌 0L5Z7
    │
    ├──→ 检测承诺: 安排房间
    │        │
    │        └──→ 推荐酒店
    │              │
    │              └──→ 一键预订
    │
    └──→ 检测提议: 小酌
             │
             └──→ 推荐餐厅
                   │
                   └──→ 一键订座
```
