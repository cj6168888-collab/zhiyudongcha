# UI/UX 规范（CANON）

> 本文件是 **Web 客户端与相关端** 的体验纲领，与 [CONSTITUTION.md](./CONSTITUTION.md) 中的体验条款一致。根目录 `design_guidelines.md` 保留移动端/Avatar 等 **场景化细则**；若冲突，以 **本 CANON + 宪法** 为准。

**版本**：1.0.0 **日期**：2026-04-19

---

## 1. 设计系统基座

| 项 | 选择 | 说明 |
|----|------|------|
| 组件库 | shadcn/ui（new-york） | 见 `components.json` |
| 样式 | Tailwind CSS v4 + CSS 变量 | `client/src/index.css` |
| 图标 | Lucide React | 与 shadcn 一致 |
| 动效 | 克制使用 | 核心流程优先稳定与可读 |

**原则**：不引入第二套未文档化的组件范式；自定义组件放在 `client/src/components/`，并复用 `@/components/ui`。

## 2. 双轨信息架构（IA）

### 2.1 个人轨 vs 组织轨

- **必须在导航或顶层切换器上区分**「个人空间」与「当前组织 / 舰队」；用户始终清楚上下文。
- **默认不假设** 个人内容对组织可见；若共享，需明确路径（分享、移动到组织库等）。

### 2.2 文案调性

- **可信、尊重、不操纵**：避免制造虚假紧迫感；涉及授权、记忆、数据上传时 **后果可见**。
- **中文为主**：产品面向中文用户时，主要流程使用简体中文；技术错误信息可对开发者双语，对用户保持可读中文。

---

## 3. 关键流程 UX 要求

| 流程 | 要求 |
|------|------|
| 登录 / 注册 | 错误提示明确、可恢复；未来接入职业与 Agent 选项时 **步骤可跳过与可回退**（若产品允许） |
| 授权与敏感操作 | 二次确认或明确说明范围；与后端权限拒绝信息 **文案对齐** |
| 长任务 | 加载状态、可取消（若适用）、失败可重试 |
| 组织邀请 | 邀请者、组织名、权限级别可见 |

---

## 4. 无障碍与可读性

- 参考仓库内 `docs/ACCESSIBILITY_MIGRATION_GUIDE.md` 与既有审计报告；新页面至少满足：
  - 键盘可聚焦主要操作；
  - 对比度与字号不低于当前设计系统基线；
  - 图标按钮提供 `aria-label` 或可见文本。

---

## 5. 与「五大专家」等能力的界面

- **能力未授权**：禁用或引导开通，不展示虚假可用状态。
- **专家输出**：区分「建议」与「事实」；涉及法律/财务等高风险领域时 **保留免责声明区域**（文案由产品最终审定）。

---

## 6. 文件与代码组织

- 页面级路由与布局：`client/src/pages/`（以现有结构为准）。
- 共享布局（个人/组织壳）：新增时避免复制粘贴，抽 **布局组件**。

---

## 7. 修订

视觉大改版需更新本文件版本号，并在 [FOUNDATION_INDEX.md](./FOUNDATION_INDEX.md) 中无需重复，但 PR 说明需引用。
