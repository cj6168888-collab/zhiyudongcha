# 对话 UI

## 定位

对话 UI 是主入口，不是普通聊天框。

它要同时支持陪伴、理解、结构化、确认、执行和回流。

## 基本布局

移动端：

- 顶部：当前身份、状态、语音/记忆/权限状态。
- 中部：对话流。
- 底部：语音按钮、输入框、附件、快捷动作。
- 浮层：理解卡片、确认卡片、执行进度。

## 对话卡片类型

- 普通消息。
- 语音转写。
- 理解结果。
- 候选记忆。
- 任务草案。
- 项目更新。
- 风险确认。
- 执行进度。
- 结果回报。
- 蜂群广播。

## 理解结果卡

显示：

- 我理解的是。
- 涉及人物。
- 涉及项目。
- 可能任务。
- 风险。
- 缺失信息。

主人可以：

- 确认。
- 修改。
- 忽略。
- 转成任务。
- 转成项目。
- 存为记忆。

## 闲聊体验

闲聊时不要频繁弹出结构化卡片。

可以轻量显示：

- 她正在听。
- 她的情绪/声音状态。
- 必要时一个小提示：“这句话要不要我记住？”

## 任务体验

任务模式必须清晰：

- 目标。
- 步骤。
- 当前状态。
- 是否需要确认。
- 结果。
- 证据。

## 风险确认

确认卡必须写清：

- 动作。
- 数据。
- 目标对象。
- 影响。
- 是否可撤回。
- 替代方案。

按钮：

- 确认执行。
- 只生成草稿。
- 修改范围。
- 取消。

## 语音

语音输入要支持：

- 按住说话。
- 持续聆听。
- 转写可编辑。
- 说话人标注。
- 声纹提示。

语音输出要支持：

- 当前音色。
- 暂停。
- 重读。
- 文字同步。
