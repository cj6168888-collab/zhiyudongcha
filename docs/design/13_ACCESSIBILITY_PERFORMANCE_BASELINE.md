# 可访问性与性能基线

## 目的

本文件承接旧 UI/UX 审计中的有效结论，把可访问性和性能要求变成新界面的硬基线。

旧参考：

- [../UI_UX_AUDIT_REPORT.md](../UI_UX_AUDIT_REPORT.md)
- [../frontend-ux-deep-audit-report-v2.md](../frontend-ux-deep-audit-report-v2.md)
- [../ACCESSIBILITY_MIGRATION_GUIDE.md](../ACCESSIBILITY_MIGRATION_GUIDE.md)

## 可访问性最低标准

新页面至少满足：

- 主要操作可键盘访问。
- 焦点指示器可见。
- 触控目标不小于 44px。
- 图标按钮有 `aria-label` 或可见文本。
- 表单 label 与 input 关联。
- 错误信息使用 `role="alert"` 或 `aria-live`。
- 不只用颜色表达状态。
- 支持 `prefers-reduced-motion`。
- 文本不溢出、不遮挡。

## 颜色对比

最低要求：

- 正文文字对比度 >= 4.5:1。
- 大号文字对比度 >= 3:1。
- 交互边界和焦点指示 >= 3:1。
- 禁用状态仍需可辨识，不得低到不可读。

风险确认、错误、删除、外传相关文案必须优先保证可读。

## ARIA 基线

必须覆盖：

- Dialog：`aria-modal`、标题、描述。
- Dropdown/Menu：展开状态、可读菜单项。
- Tabs：`aria-selected`、`aria-controls`。
- Accordion：`aria-expanded`。
- Toast/动态状态：`aria-live`。
- 语音状态：正在听、正在转写、正在说话。

## 权限和错误引导

权限拒绝后必须给出：

- 发生了什么。
- 哪项权限被拒绝。
- 为什么需要。
- 如何重新开启。
- 替代路径。

麦克风、通知、文件、照片、辅助功能权限都必须有独立引导。

## WebSocket 和实时状态

实时能力必须显示：

- 已连接。
- 正在重连。
- 已断开。
- 重连失败。
- 当前任务是否受影响。

重连建议：

- 指数退避。
- 最多重试次数。
- 可手动重试。
- 不重复提交高风险指令。

## 性能基线

移动端目标：

| 指标 | 目标 |
| --- | --- |
| 首屏可见 | < 2.5s on 4G |
| 主要交互可用 | < 3.5s on 4G |
| 语音转写首包 | P95 < 1000ms |
| 页面切换响应 | P95 < 300ms |
| 长任务状态更新 | P95 < 1000ms |

桌面端目标：

| 指标 | 目标 |
| --- | --- |
| 首屏可见 | < 2s |
| 大列表滚动 | 无明显卡顿 |
| 多面板切换 | P95 < 300ms |
| 远程控制回执 | P95 < 500ms |

## 动画

动画只服务状态理解：

- 聆听。
- 思考。
- 执行。
- 完成。
- 风险。
- 梦境。

禁止：

- 危机模式卖萌。
- 长任务使用无法取消的装饰动画。
- 大量同时触发布局动画。

## 验收

每个新页面至少检查：

- 键盘走一遍主流程。
- 移动端 360px 宽度不溢出。
- 触控按钮不小于 44px。
- 主要图标按钮可被读屏识别。
- 权限拒绝有恢复路径。
- 加载、空、错误、断线状态都有明确文案。
