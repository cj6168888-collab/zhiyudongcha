# Design Tokens 与组件状态

## 目的

本文件把设计原则落成可执行规格，避免每个页面重新发明视觉语言。

生语助手的设计目标是：强能力轻呈现、边界清楚、风险明确、长期可信。

## Token 原则

1. Token 服务可读性和状态表达，不服务装饰堆叠。
2. 暗色底可以有生命感，但不能压低文字对比度。
3. 风险、确认、审计、隐私状态必须比品牌装饰更醒目。
4. 移动端触控优先，桌面端信息密度优先。

## 颜色语义

| Token | 用途 |
| --- | --- |
| `surface.base` | 页面底色 |
| `surface.raised` | 普通卡片和面板 |
| `surface.sunken` | 输入区、代码区、低层级容器 |
| `text.primary` | 主文字 |
| `text.secondary` | 辅助文字 |
| `text.muted` | 弱提示 |
| `accent.intent` | 当前主行动 |
| `accent.memory` | 记忆、知识、来源 |
| `accent.task` | 任务、执行、计划 |
| `accent.swarm` | 蜂群、组织、节点 |
| `risk.low` | L0/L1 低风险 |
| `risk.medium` | L2 草拟和中风险 |
| `risk.high` | L3 外部影响 |
| `risk.critical` | L4 高风险 |
| `risk.blocked` | L5 禁止或交给主人 |

## 间距

建议使用 4px 基础单位：

| Token | 值 | 用途 |
| --- | --- | --- |
| `space.1` | 4px | 图标和文字间距 |
| `space.2` | 8px | 卡片内部小间距 |
| `space.3` | 12px | 表单项间距 |
| `space.4` | 16px | 卡片 padding |
| `space.6` | 24px | 区块间距 |
| `space.8` | 32px | 页面主间距 |

## 圆角

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius.control` | 8px | 按钮、输入框、选择器 |
| `radius.card` | 8px | 普通卡片 |
| `radius.sheet` | 12px | 底部弹层、抽屉 |
| `radius.modal` | 12px | 确认弹窗 |

避免卡片套卡片导致层级混乱。

## 字体层级

| Token | 用途 |
| --- | --- |
| `type.pageTitle` | 页面标题 |
| `type.sectionTitle` | 区块标题 |
| `type.cardTitle` | 卡片标题 |
| `type.body` | 正文 |
| `type.caption` | 来源、时间、状态 |
| `type.mono` | requestId、代码、日志片段 |

不要用超大标题装饰工作型页面。

## 组件状态

所有关键组件至少支持：

- `idle`
- `hover`
- `focus`
- `active`
- `loading`
- `disabled`
- `success`
- `warning`
- `error`
- `blocked`

移动端没有 hover 时，必须有 pressed 和 focus-visible 替代。

## 关键组件规格

### 对话消息

必须区分：

- 主人输入。
- 助手回复。
- 语音转写。
- 系统状态。
- 风险确认。
- 执行结果。

状态字段：

- 来源。
- 时间。
- 是否已写入记忆。
- 是否触发任务。
- 是否含敏感内容。

### 理解卡

必须显示：

- 我理解的是。
- 置信度或不确定提示。
- 人物、项目、任务、时间。
- 缺失信息。
- 风险。

操作：

- 确认。
- 修改。
- 忽略。
- 转任务。
- 转项目。
- 存记忆。

### 记忆卡

必须显示：

- 内容摘要。
- 类型。
- 来源。
- 敏感等级。
- 置信度。
- 最近使用。
- 私密或蜂群共享状态。

操作：

- 修改。
- 删除。
- 查看来源。
- 降权。
- 设为私密。
- 共享到蜂群。

### 任务卡

必须显示：

- 目标。
- 状态。
- 风险等级。
- 当前步骤。
- 下一步。
- 截止时间。
- 证据。

任务状态颜色不能只靠颜色表达，必须同时有文本或图标。

### 风险确认卡

必须高于普通卡片层级。

必须显示：

- 动作。
- 数据范围。
- 目标对象。
- 影响。
- 是否可撤回。
- 替代方案。

按钮顺序：

1. 修改范围。
2. 只生成草稿。
3. 取消。
4. 确认执行。

确认执行按钮必须视觉上明确，但不能诱导误触。

### 授权开关

必须显示：

- 权限名称。
- 用途。
- 数据范围。
- 本地/云端处理状态。
- 是否进入长期记忆。
- 是否进入蜂群。

关闭入口必须和开启入口同等可达。

## 空状态

空状态不写功能说明书，只给下一步：

- 没有任务：可以从对话中创建任务。
- 没有记忆：她会先把重要内容放进候选记忆。
- 没有蜂群：可以创建蜂群或加入已有蜂群。
- 没有审计：还没有发生需要记录的关键动作。

## 加载状态

加载状态必须说明当前阶段：

- 正在理解。
- 正在查找资料。
- 正在生成草稿。
- 等待确认。
- 正在执行。
- 正在验证结果。

长任务必须可取消或后台运行。

## 错误状态

错误提示必须包含：

- 发生了什么。
- 是否造成影响。
- 现在能做什么。
- requestId。

禁止只显示“失败了”。

## 响应式验收

移动端：

- 触控目标不小于 44px。
- 文本不溢出。
- 底部输入不遮挡内容。
- 高风险确认不被键盘遮挡。

桌面端：

- 主内容、上下文、审计面板可并列。
- 多面板不能互相挤压到不可读。
- 表格和日志支持横向滚动或列折叠。
