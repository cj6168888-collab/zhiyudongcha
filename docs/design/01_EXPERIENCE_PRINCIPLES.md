# 体验原则

## 一句话原则

强能力轻呈现。

底层可以复杂，但界面只展示主人当前真正需要知道和操作的东西。

## 主入口是对话

主人首先应该能说：

```text
帮我处理一下这个事。
```

页面用于确认、展示、管理和追溯，不应让用户在功能迷宫里找按钮。

## 模式决定体验

不同对话模式对应不同体验：

| 模式 | 体验 |
| --- | --- |
| 闲聊陪伴 | 轻松、柔和、不强行结构化 |
| 任务执行 | 清晰、结构化、可追踪 |
| 战略探讨 | 观点、路线、对比、推演 |
| 记忆捕捉 | 来源、置信度、是否保存 |
| 危机守护 | 稳定、醒目、少装饰 |
| 蜂群指挥 | 权威、态势、审计明确 |

## 不堆仪表盘

看板不是产品价值本身。

优先闭环：

```text
输入 -> 理解 -> 确认 -> 执行 -> 回报 -> 记忆
```

## 高风险必须清楚

确认不能只写“确定吗”。

必须说明：

- 要做什么。
- 影响谁。
- 会发送、删除、共享什么。
- 是否可撤回。
- 有没有替代方案。

## 记忆可见

主人要能看到：

- 她记住了什么。
- 为什么记住。
- 来源在哪里。
- 是否可信。
- 能不能改。
- 能不能删。
- 是否进入蜂群。

## 个性化有仪式感

觉醒不是注册表单，而是关系建立。

名字、称呼、关系、人格、声音、边界都应该自然完成。

## 蜂群强调边界

蜂群界面必须区分：

- 我的。
- 蜂群的。
- 已共享的。
- 被审计的。
- 异常的。

## 视觉方向

- 暗色底，但不压抑。
- 有生命感，但不过度装饰。
- 工作区克制、清晰、高信息密度。
- 对话区温暖、有呼吸感。
- 风险区严肃、明确。
- 梦境和头像可以更柔和。

## 移动端优先

移动端是随身助手主体验。桌面端适合：

- 大文档。
- 项目管理。
- 蜂群监控。
- 执行追踪。
- 复杂配置。
