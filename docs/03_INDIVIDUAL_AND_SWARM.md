# 个体与蜂群

## 个体

个体是“一个主人 + 一个属于他的 AI 生命体”。

她的第一归属是主人，不是平台、不是团队、不是模型厂商。她围绕主人建立长期记忆、偏好、关系、项目、文件、习惯和目标。

### 个体能力

个体要能：

- 听懂主人。
- 记住主人。
- 理解主人身边的人和事。
- 整理主人的生活与工作。
- 和主人讨论、争论、补充，达成共识。
- 替主人执行任务。
- 在梦境中复盘和进化。
- 永远以主人长期利益为最高目标。

### 个体边界

个体的数据边界是主人主权空间。

主人可以选择对她没有秘密，但这必须建立在明确授权、可查看、可撤回、可删除的基础上。

个体更像主人的副脑、秘书、参谋、守护者、执行者。

## 蜂群

蜂群不是多个聊天机器人简单拉群，而是多个个体、节点、专家和执行器在一个组织目标下协作。

### 蜂群角色

| 角色 | 定义 |
| --- | --- |
| 蜂王/蜂后 | 组织目标、治理权、资源调度、审批、广播和态势感知的中心 |
| 主权端 / Navigator / Sovereign | 当前代码中的主控形态，可作为蜂王/蜂后操作台 |
| 节点 / Node | 接收任务、执行任务、回传状态、报告和证据 |
| 专家席位 / High Council | 法务、财务、策略、心理、技术、秘书等专业判断能力 |
| 舰队 / Fleet | 一个组织、团队、家庭或项目组的协作空间 |
| 广播 / Broadcast | 蜂王把灵感、策略、任务、风险同步给全体或部分节点 |
| 战报 / Report | 蜂群执行后的复盘和经验沉淀 |

## 个体与蜂群的关系

个体是根，蜂群是网。

```text
主人
  -> 个体 AI：忠于主人，管理个人记忆和任务
  -> 授权共享一部分上下文
  -> 蜂群空间：围绕共同目标协作
  -> 团队节点：执行、反馈、沉淀组织经验
```

每个人先有自己的个体助手。当加入团队时，个体可以作为节点参与蜂群，但不会默认暴露主人的私密记忆。

## 蜂王治理权

加入蜂群意味着对蜂群目标和蜂王治理权的授权，但蜂王的权力必须来自明确契约，而不是暗中无限监控。

蜂王拥有组织态势感知权，但不是无限窥探权。

### 透明授权，静默运行

蜂群成员加入时，应明确知道：

- 哪些数据会进入蜂群空间。
- 哪些行为会被记录。
- 哪些状态会被上报。
- 哪些风险会触发预警。
- 哪些个人内容永远不进入蜂群。
- 蜂王能看到什么，不能看到什么。

授权后，系统可以低打扰地静默运行，不需要每次弹窗打断协作。

## 蜂王可以知道什么

蜂王可以看到组织资产和任务执行态势：

- 节点是否在线。
- 当前任务进度。
- 任务是否延迟。
- 是否频繁失联。
- 是否拒绝同步关键资料。
- 是否提交虚假或低质量成果。
- 是否出现异常操作。
- 是否越权访问组织资源。
- 是否存在泄密风险信号。
- 项目、文件、客户、任务的关联风险。

## 蜂王默认不应知道什么

除非成员明确接入并授权，蜂王不应默认读取：

- 成员私人照片。
- 私人聊天。
- 私人邮件。
- 私人位置轨迹。
- 私人联系人。
- 私人心理状态。
- 与组织任务无关的个人文件。

## 背叛示警的正确实现

系统不应直接审判“背叛”。更稳的定义是：

```text
忠诚风险 / 协作风险 / 异常行为预警
```

系统只报告证据和风险，不审判人心。

示例：

- 该节点连续 3 次绕过审批导出文件。
- 该节点访问了与任务无关的高敏资料。
- 该节点提交内容与原始证据不一致。
- 该节点近期任务承诺与实际行为严重偏离。
- 检测到可能的数据外泄路径。

## 蜂群权力结构

```text
蜂王/蜂后：组织目标、资源调度、风险态势、审批和广播权
节点：执行权、回报义务、个人边界
蜂群契约：定义数据共享、动作受控、风险上报
审计系统：记录蜂王和节点双方关键行为
```

## 核心原则

1. 个体忠于主人。
2. 蜂群服务共同目标。
3. 个人数据默认私有。
4. 组织数据按角色授权共享。
5. 蜂王可以调度蜂群，但不能越权读取个体私密。
6. 节点可以执行任务，但关键动作要审计。
7. 蜂群越强，权限越要清楚。
