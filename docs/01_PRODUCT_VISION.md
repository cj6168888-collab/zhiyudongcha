# 产品愿景

## 核心定义

生语助手是一个“功能强大，但操作简单”的全能 AI 助手。她不是传统意义上的聊天机器人，也不是堆满功能入口的管理系统，而是主人的长期副脑、守护者、参谋、秘书、执行者和组织协作中枢。

用户不应该学习复杂功能。用户只需要自然表达，系统在背后完成理解、拆解、记忆、整理、执行、复盘和进化。

每个个体都应先通过身份觉醒建立名字、称呼、关系、人格、声音、记忆边界和执行边界。同一个系统，对不同主人应该长成不同的她。

## 产品灵魂

她会倾听，会记住，会思考，会行动，会成长，还能带动团队。

这句话是所有设计和开发取舍的最高产品原则。

## 用户价值

### 对个人

她帮助主人管理生活和工作中的所有上下文，包括人、事、文件、项目、承诺、偏好、目标、风险和长期记忆。

她不是临时回答问题，而是持续理解主人，越来越懂主人，越来越会替主人办事。

### 对工作

她把聊天、会议、电话、邮件、照片、文件和碎片想法变成结构化资产：项目、任务、纪要、文档、提醒、风险、合同、报告和知识库。

### 对组织

她可以进入蜂群，成为节点或主权端的一部分，帮助团队同步背景、分派任务、回传结果、发现异常、沉淀经验。

## 四个主体验

### 1. 聊天界面：主入口

聊天界面是最重要的入口。它必须承担自然语言、语音、文件、图片、邮件、截图、任务和 App 操作的总调度入口。

她在聊天里要能：

- 倾听：语音、会议、电话、碎片输入都能接住。
- 分辨：知道谁说了什么、谁承诺了什么、谁是关键人物。
- 记住：把信息沉淀成人物、项目、任务、偏好、知识和证据。
- 整理：自动归档、打标签、建关系、生成摘要和时间线。
- 探讨：能对话、建议、补充、质疑、争论，帮助主人达成共识。
- 执行：接任务、拆任务、设提醒、循环执行、调用工具、回报结果。
- 陪伴：当主人只是闲聊、吐槽或放空时，她可以轻松、幽默、自然一点，不强行把每句话变成任务。

理想体验是：主人说一句“帮我把刚才这个事推进一下”，她知道“这个事”是什么、涉及谁、上次到哪、下一步该怎么做。

### 2. 工作界面：成果中心

工作界面不是让用户手动填表，而是展示她整理出来的工作世界。

她要能自动：

- 建立项目。
- 总结项目背景。
- 完善目标、成员、资料、风险、进度。
- 生成文档、建议、提醒、战报。
- 发现遗漏和矛盾。
- 调用法务、财务、策略、心理、技术、秘书等专家能力。

### 3. 梦境界面：进化和反思

梦境不是装饰动画，而是后台成长机制。

梦境中她要能：

- 夜间复盘当天信息。
- 整理长期记忆。
- 发现关系变化、项目风险和重复模式。
- 总结主人的偏好和决策风格。
- 模拟明天可能发生的问题。
- 生成醒来建议。
- 优化自己的工具选择、知识结构和执行策略。

梦境的意义是：她不是每次从零回答，而是越来越懂主人。

### 4. 蜂群界面：团队协作

蜂群不是多个聊天机器人拉群，而是多个个体/节点在共同目标下协作。

蜂群支持：

- 主人创建或加入团队。
- 蜂王/蜂后定义目标、授权资源、发布任务。
- 节点接收任务、执行、回传。
- 专家席位提供专业判断。
- 系统发现异常、生成预警、沉淀组织经验。

## 第一产品闭环

第一阶段必须先跑通这条闭环：

```text
聊天/语音/文件输入
  -> 信息理解
  -> 自动生成记忆/项目/任务
  -> 和主人确认共识
  -> 执行或定时执行
  -> 工作台呈现结果
  -> 梦境复盘
  -> 第二天主动提醒
```

这条闭环跑通，产品就活了。后续所有能力都围绕这颗心脏扩展。

## 反臃肿原则

生语助手不追求把所有功能都内置成页面，而是追求能完成任务。

她可以借助：

- 手机 App。
- 电脑软件。
- 浏览器。
- 邮件客户端。
- 文件系统。
- 日历和联系人。
- 地图、打车、支付、办公套件等第三方工具。

因此，核心不是“做很多模块”，而是建设感知、记忆、推理、授权、执行和回流能力。
