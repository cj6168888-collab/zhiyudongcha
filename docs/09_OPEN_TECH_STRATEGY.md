# 开放技术战略

## 核心判断

AI 技术正在高速演进。昨天昂贵、困难或不稳定的能力，今天可能已经变成 API、开源模型、系统工具或手机平台能力。

因此，生语助手不能闭门造车，也不能把某个模型、某个供应商、某套固定工具当成永久核心。她必须成为一个开放吸收型 AI 操作系统。

## 技术定位

生语助手不和模型厂商拼底层大模型。她的核心价值是：

- 主人的长期记忆。
- 主人的世界模型。
- 主权守护协议。
- 权限、隐私、预算和审计。
- 任务执行闭环。
- 对外部模型、工具、App 和设备的统一调度。

外部能力可以替换，主人主权层不能替换。

## 一句话原则

不押注某一个模型，不迷信自研一切，不把能力写死；只掌握主权、记忆、权限、执行闭环，把外部最强能力随时接进来。

## 五层开放架构

```text
主权守护层
  权限、隐私、审计、预算、风险确认

主人世界模型层
  永久记忆、知识库、人物、项目、任务、偏好

智能路由层
  模型路由、专家路由、工具选择、成本控制

执行适配层
  API、MCP、手机 App、电脑、浏览器、文件、邮件、日历

外部能力生态层
  OpenAI、DeepSeek、通义千问、Claude、本地模型、开源工具、第三方 App
```

## 不闭门造车

默认策略：

1. 已有成熟能力，优先接入。
2. 没有成熟能力，再做适配层。
3. 只有当能力涉及主权、记忆、权限、审计、长期数据结构时，才作为核心自研。
4. 外部能力越强，越要先接入主权守护协议。

## 模型可插拔

模型是能力供应商，不是系统主人。

应支持：

- OpenAI。
- DeepSeek。
- 通义千问 / DashScope。
- Claude。
- 本地模型。
- 专用 OCR / ASR / TTS / Embedding / Vision 模型。
- 后续出现的新模型。

模型路由不应写死在页面里，而应由任务类型、风险等级、隐私等级、成本预算和可用性共同决定。

### 路由依据

| 维度 | 说明 |
| --- | --- |
| 任务类型 | 聊天、摘要、推理、代码、法务、财务、视觉、语音 |
| 隐私等级 | 本地优先、可云端、禁止外传 |
| 成本预算 | 优先低成本，必要时升级强模型 |
| 延迟要求 | 实时语音和 App 操作优先低延迟 |
| 可靠性 | 失败自动降级或切换 |
| 专业性 | 专家任务走专业模型或专业提示链 |

## 工具可插拔

工具包括：

- API 工具。
- MCP 工具。
- 本地命令。
- 浏览器操作。
- 文件解析。
- 邮件和日历。
- 手机 App 操作。
- 电脑软件操作。
- 蜂群节点能力。

工具注册必须描述：

- 工具能做什么。
- 需要什么权限。
- 会读取什么数据。
- 会不会影响外部世界。
- 风险等级。
- 预算消耗。
- 审计字段。
- 失败回滚或补救方式。

## App 操作优先于重复造功能

很多能力不必内置成复杂页面。

如果手机或电脑已有成熟 App，助手应优先学会操作它们：

- 邮件。
- 日历。
- 地图。
- 网盘。
- 办公套件。
- 浏览器。
- 通讯工具。
- 相册。
- 文件管理器。
- 项目管理工具。

产品界面负责表达目标、确认风险、展示结果；具体执行可以借助外部 App。

## 技术雷达机制

系统应建立技术雷达，定期扫描和评估：

- 新模型。
- 新工具调用协议。
- 新 Agent 框架。
- 新端侧模型。
- 新语音/视觉/OCR 能力。
- 新手机/电脑自动化能力。
- 新开源项目。
- 新安全风险。

每个候选技术用统一标准评估：

| 维度 | 问题 |
| --- | --- |
| 能力 | 它解决什么问题？是否明显优于现有方案？ |
| 成本 | token、API、部署、维护成本如何？ |
| 隐私 | 是否需要外传敏感数据？ |
| 稳定性 | 是否适合进入主流程？ |
| 可替换性 | 是否会形成供应商锁定？ |
| 接入难度 | 是否能通过适配层接入？ |
| 守护兼容 | 能否接入权限、确认、审计和预算系统？ |

## 新能力接入流程

```text
发现新能力
  -> 技术雷达登记
  -> 小样本验证
  -> 主权守护评估
  -> 适配层封装
  -> 模型/工具路由注册
  -> 进入灰度任务
  -> 观察成本、质量和风险
  -> 正式进入能力池
```

## 禁止事项

1. 禁止把供应商能力直接写死到核心业务流程。
2. 禁止绕过主权守护协议直接调用外部模型或工具处理敏感信息。
3. 禁止为了演示效果做不可审计的自动执行。
4. 禁止重复造已有成熟 App 能力，除非它是主权、记忆或安全底座。
5. 禁止把“某模型说可以”当成权限依据。

## 对当前项目的实现要求

后续代码应逐步形成：

- `ModelRouter`：统一模型路由。
- `ToolRegistry`：统一工具注册。
- `PermissionGate`：统一权限闸门。
- `RiskClassifier`：动作风险分级。
- `ExecutionAdapter`：API、App、浏览器、电脑、手机的统一执行适配。
- `AuditTrail`：统一审计。
- `TechRadar`：新能力登记和评估。

## 结论

生语助手必须像生命体一样吸收外部新能力，但她的灵魂不能外包。

外部模型和工具只是雇来的能力；主人主权、长期记忆、守护协议和任务闭环，才是系统真正的根。
