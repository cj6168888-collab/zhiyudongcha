# 语言与风格规范

## 编码

所有新文件必须使用 UTF-8。

禁止新增乱码中文注释。现有乱码文件可以在触及时逐步修复，但不要为了无关任务大规模改动。

## 语言

- 主语言：TypeScript。
- 前端：React + TypeScript。
- 后端：Node.js + Express + TypeScript。
- 数据模型：Drizzle schema + shared types。

## 类型

新代码应优先强类型。

要求：

- API 入参用 zod 校验。
- API 出参定义类型。
- 关键枚举进入 `shared/`。
- 避免无约束 `any`。
- 不能因为赶进度绕过类型边界。

## 注释

注释应解释“为什么”，不是重复“做什么”。

适合注释：

- 权限原因。
- 风险降级原因。
- 复杂状态机。
- 兼容旧数据。
- 安全边界。

不适合注释：

- “设置变量”。
- “调用函数”。
- 与代码明显重复的说明。

## 中文与英文

代码标识使用英文。

面向用户文案可以中文。

建议：

- 文件名、函数名、变量名：英文。
- 用户界面文案：中文为主。
- 技术文档：中文为主，必要名词保留英文。
- API 错误码：英文大写或 snake/camel 风格统一。

## UI 文案

文案必须服务使用，不要堆概念。

避免：

- 过度玄学。
- 过度军事化。
- 过度解释功能。
- 页面里写大段说明。

推荐：

- 简短。
- 具体。
- 可执行。
- 在需要确认风险时说明清楚。

## 错误信息

错误分两层：

- 用户可见：清楚、短、可行动。
- 开发可见：错误码、requestId、details、日志。

不要把内部堆栈直接返回给前端。

## 文件格式

- 使用 LF 或仓库既有格式，避免无意义格式 churn。
- JSON 使用 2 空格。
- Markdown 使用清晰标题和短段落。
- 不在文档中粘贴密钥、token、账号密码。
