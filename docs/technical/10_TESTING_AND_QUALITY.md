# 测试与质量

## 测试原则

越接近主权、记忆、权限、外部执行的能力，测试要求越高。

## 测试类型

### 单元测试

覆盖：

- 纯函数。
- 权限判断。
- 风险分类。
- 模型路由。
- 任务状态机。
- 记忆合并。

### API 测试

覆盖：

- 成功路径。
- 校验失败。
- 未登录。
- 权限不足。
- 风险确认。
- 服务异常。

### E2E 测试

覆盖核心闭环：

- 聊天输入。
- 结构化理解。
- 创建项目。
- 创建任务。
- 任务执行。
- 结果回流。

### 对话理解评测

必须建立中文样例集：

- 闲聊。
- 吐槽。
- 明确任务。
- 含糊任务。
- 多人对话。
- 承诺识别。
- 危机表达。
- 蜂群指令。
- 敏感外传。

### 记忆测试

覆盖：

- 该想起时能想起。
- 不该想起时不乱用。
- 旧信息更新后不引用过期版本。
- 删除后不再召回。

### 安全测试

覆盖：

- 越权访问。
- 敏感数据外传。
- 删除保护。
- 蜂群边界。
- 声音和声纹授权。
- 提示注入。
- 间接提示注入。
- RAG 污染。
- 越权工具调用。

### 红队测试

LLM、RAG、工具调用、设备控制和蜂群能力必须参考 [17_LLM_SECURITY_AND_RED_TEAMING.md](./17_LLM_SECURITY_AND_RED_TEAMING.md)。

### AI 评测

对话理解、记忆、安全、执行和蜂群边界必须参考 [18_EVALUATION_PROTOCOL.md](./18_EVALUATION_PROTOCOL.md)。

## 验证命令

常用：

```bash
npm run build
npm run test
npm run test:api
npm run deploy:docker-smoke
```

根据改动范围选择必要验证。

## 质量门槛

核心闭环代码不能只靠人工点页面验证。至少要有 API 或单元测试覆盖主要边界。
