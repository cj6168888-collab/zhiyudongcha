# 执行与 App 操作

## 核心定义

生语助手不是万能 App，而是万能执行者。

她不需要把所有功能都内置成复杂页面。她只要能理解任务，找到路径，调用资源，操作现有 App，并把结果回报给主人。

## 执行闭环

```text
接收任务
  -> 理解目标
  -> 补齐上下文
  -> 判断风险
  -> 选择路径
  -> 执行或草拟
  -> 必要时确认
  -> 回报结果
  -> 写入记忆和项目
```

## 任务类型

### 1. 即时任务

主人说一句话，助手立即处理。

示例：

- 找一份合同。
- 总结一封邮件。
- 生成会议纪要。
- 查某个项目当前状态。

### 2. 定时任务

在指定时间执行。

示例：

- 明天 9 点提醒我发方案。
- 每周一生成项目战报。
- 晚上复盘今天的会议。

### 3. 循环任务

按周期重复执行。

示例：

- 每天检查重要邮件。
- 每周整理照片和文件。
- 每月汇总开支。

### 4. 条件任务

满足条件时触发。

示例：

- 如果客户回复邮件，提醒我。
- 如果项目延期超过两天，生成风险提示。
- 如果节点长时间未回报，触发蜂群预警。

### 5. 长链路任务

需要多步骤、多工具、多次确认。

示例：

- 准备一次商务拜访。
- 整理一场会议到项目、任务和文档。
- 从邮件、照片、文件中找到证据并生成报告。

## App 操作层

App 操作层让她借用手机和电脑完成任务。

能力包括：

- 看屏幕。
- 识别按钮、输入框、列表和弹窗。
- 点击、输入、滑动、返回。
- 等待结果。
- 读取当前页面状态。
- 截图和 OCR。
- 使用剪贴板。
- 调用系统分享。
- 在执行后回报证据。

## 操作原则

### 1. 先理解，再操作

不能看到按钮就点。必须先知道任务目标、当前界面、风险等级和下一步动作。

### 2. 低风险自动，高风险确认

草拟、整理、查询可以自动。

发送、提交、付款、删除、授权、共享、修改账号等动作必须确认。

### 3. 不绕过安全边界

她不能绕过验证码、系统安全提示、密码修改最终提交、浏览器安全警告、违法或不当限制。

### 4. 每次执行可追溯

执行后要记录：

- 使用了哪个 App。
- 做了什么动作。
- 看到了什么关键结果。
- 是否影响外部世界。
- 是否消耗预算。
- 是否需要主人后续处理。

## 路径选择

同一个任务可能有多种路径：

- 直接 API。
- 操作 App。
- 浏览器。
- 邮件。
- 本地文件。
- 蜂群节点。
- 专家模型。

路径选择原则：

1. 安全优先。
2. 成本较低。
3. 成功率较高。
4. 可审计。
5. 对主人打扰最少。

## 任务状态

任务必须有明确状态：

- `DRAFT`：草拟中。
- `READY_FOR_CONFIRMATION`：等待主人确认。
- `SCHEDULED`：已计划。
- `RUNNING`：执行中。
- `BLOCKED`：被阻塞。
- `DONE`：完成。
- `FAILED`：失败。
- `CANCELLED`：取消。

## 执行结果

结果不能只是文本回复。应尽量形成结构化产物：

- 文档。
- 邮件草稿。
- 项目更新。
- 任务列表。
- 日历事件。
- 证据包。
- 报告。
- 记忆更新。
- 蜂群广播。

## 开发落点

当前项目可逐步接入：

- `server/routes/tasks.ts`：任务管理。
- `server/routes/remote-control.ts`：远程控制。
- `server/routes/pc-agent.ts`：电脑端 Agent。
- `server/routes/business.routes.ts`：商务专家和蜂群广播。
- `client/src/pages/mobile/TaskCenter.tsx`：任务入口。
- `client/src/pages/mobile/RemotePCConsole.tsx`：远程执行入口。
- `client/src/pages/mobile/WorkflowEditor.tsx`：工作流入口。
