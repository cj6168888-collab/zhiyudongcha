# 核心能力架构

## 总体架构

生语助手的能力不按页面划分，而按生命体能力划分。

```text
感知层
  -> 理解层
  -> 记忆层
  -> 推理层
  -> 对话共识层
  -> 执行层
  -> 回流层
  -> 梦境进化层
```

页面只是能力的入口和呈现，不应成为能力边界。

## 1. 感知层

感知层负责接住主人世界里的信息。

输入包括：

- 文字聊天。
- 语音和会议。
- 电话和录音。
- 照片和截图。
- 文件和附件。
- 邮件。
- 日历。
- 联系人。
- 手机和电脑屏幕。
- App 状态。
- 浏览器页面。
- 蜂群节点回报。

关键能力：

- 声纹识别。
- 说话人分离。
- OCR。
- 文件解析。
- 邮件解析。
- 屏幕理解。
- 场景识别。

## 2. 理解层

理解层负责把原始信息变成可行动结构。

要提取：

- 人物。
- 时间。
- 地点。
- 承诺。
- 冲突。
- 风险。
- 任务。
- 项目。
- 文件。
- 关系。
- 情绪。
- 证据。
- 主人偏好。

她必须能分辨“谁说了什么”“谁答应了什么”“什么是事实”“什么是猜测”“什么需要确认”。

## 3. 记忆层

记忆层负责永久、科学、可控地保存信息。

记忆类型：

- 原始记录。
- 摘要记忆。
- 人物记忆。
- 项目记忆。
- 任务记忆。
- 偏好记忆。
- 关系记忆。
- 证据记忆。
- 风险记忆。
- 蜂群组织记忆。

记忆必须支持查看、修改、删除、导出、权限限制和来源追溯。

## 4. 推理层

推理层负责判断、建议、争论、补充和规划。

能力包括：

- 多步推理。
- 方案比较。
- 风险评估。
- MCTS 推演。
- 专家会审。
- 反事实分析。
- 决策建议。
- 争论和质疑。
- 共识整理。

目标不是让 AI 永远顺从，而是帮助主人做更好的决定。

## 5. 对话共识层

对话不是输出答案，而是达成共识。

共识对象包括：

- 结论。
- 任务。
- 下一步。
- 负责人。
- 截止时间。
- 风险。
- 需要确认的信息。
- 可执行动作。

聊天结果应该能一键变成项目、任务、文档、提醒或执行计划。

## 6. 执行层

执行层负责真正完成任务。

执行方式包括：

- 调用后端 API。
- 操作手机 App。
- 操作电脑软件。
- 操作浏览器。
- 调用邮件、日历、联系人。
- 生成文档。
- 调用模型和专家。
- 创建循环任务和定时任务。
- 远程控制设备。
- 蜂群广播和节点调度。

执行层必须接入主权守护协议。

## 7. 回流层

每次执行后都要回流：

- 做了什么。
- 结果是什么。
- 证据在哪里。
- 是否完成。
- 是否有风险。
- 下一步是什么。
- 需要主人确认什么。

回流结果进入记忆、项目、任务、战报和梦境。

## 8. 梦境进化层

梦境层负责复盘和自我优化。

它在低打扰时段运行：

- 整理白天信息。
- 合并重复记忆。
- 发现长期模式。
- 提醒遗漏任务。
- 更新人物画像。
- 更新项目风险。
- 生成醒来建议。
- 优化工具选择策略。

梦境层不能绕过权限和预算。

## 专家系统

专家不是独立产品，而是推理层的可插拔能力。

典型专家：

- 法务专家。
- 财务专家。
- 策略专家。
- 心理/关系专家。
- 技术专家。
- 秘书/执行专家。

专家输出必须结构化，并能进入项目、任务、文档、战报和审计。

## 模型路由

模型选择应按任务类型，而不是写死在页面里。

示例：

- 普通聊天：低成本模型优先。
- 高价值推理：强模型。
- 法务/财务：专业模型或专业提示链。
- 本地隐私摘要：本地模型优先。
- 长文档整理：分块、缓存、摘要链。
- 实时语音：低延迟模型。

模型路由必须受预算系统控制。
